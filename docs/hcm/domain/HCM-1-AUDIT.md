# HCM-1 audit design

Status: complete design for review. Incorporates
[shared technical contracts](../tdd/TDD-HCM-1-LOCAL-COMMON.md).

<a id="policy"></a>

## POLICY — Safe evidence and visibility

David can read tenant operational audit, export and sensitive-access metadata.
All personas can read their own activity projection. Neither permission grants
document contents or other employee data. No editable audit UI, event deletion,
arbitrary SQL search, compliance certification or export creation is included.
Keep local history until explicit local reset; production retention remains deferred.

The Audit Log lists successful business actions generated by implemented commands.
My Activity filters actor account on the server and omits internal diagnostic fields.
Data Export Log selects actual export events; none is fabricated to populate the
screen. Sensitive Access Log records actual document/template download authorization
and separately observed stream outcome, not a claim that a human read a document.

<a id="data"></a>

## DATA — Append-only envelope and projections

Add audit_event `(tenant_id,id)`, occurred_at timestamptz, actor_account_id, action,
target_type, target_id, outcome, request_id, category (`business|sensitive-access|export`),
safe_summary jsonb and related_event_id nullable. Tenant FK and composite actor/
related-event FKs; retain actor rows (account deletion not supported). Envelope
strings have explicit bounded lengths, safe_summary is an object limited to 4 KiB
and validated against action-specific schemas in application and SQL size checks.
Runtime SELECT/INSERT only; no UPDATE/DELETE/TRUNCATE. ENABLE/FORCE RLS includes
INSERT WITH CHECK. Index tenant/occurred_at/id and tenant/actor_account_id/occurred_at/id;
category adds a tenant/category/occurred_at/id index.

Action allowlist: role created/updated/deleted, role granted/revoked, access review
started/decided/refreshed/closed, account created/enabled/disabled, document type
created/updated, template version added, document uploaded/shared, document request
created/submitted/accepted/replacement-requested/cancelled, notification preference/
template/rule changed and notification read. Summaries contain changed field names,
opaque role/type IDs, booleans, lifecycle state and bounded reason. Do not retain
names, email, filenames, free-text template/document contents or raw bodies.
Reason fields warn users not to enter sensitive details; reason is still bounded
operator-entered text, not silently stripped into a false justification.

Sensitive reads use `document.download-authorized` followed by
`document.download-completed` or `document.download-failed` with related_event_id.
Download completion means server stream completion, not proof of client receipt.
A crash may leave authorization with unknown completion; show that honestly.
Failed authorization uses safe operational logging, not an audit row that would
leak a foreign target. Failed business mutations roll back their audit append.
No failed transaction is committed solely to keep an audit row.

<a id="contract"></a>

## CONTRACT — Query and append ports

AuditItem `{id,occurredAt,actorAccountId,action,targetType,targetId,outcome,requestId,
summary}`; MyActivityItem omits requestId and returns only self-safe summary fields.
SensitiveAccessItem adds `phase,relatedEventId`; ExportItem uses `{id,occurredAt,
actorAccountId,action,targetType,targetId,outcome}` without invented download URLs.
AppendAudit input is an internal application port, not a public POST endpoint.
It accepts the verified context and validated event envelope in the caller's unit
of work; never resolves actor from event payload alone.

Outcome is `Succeeded` for committed business mutations, `Authorized` for a
sensitive stream start, and `Completed` / `Failed` for observed stream completion.
Phase is `authorization` / `stream-completion`; relatedEventId is null for the
initial event. Export outcomes are reserved for a separately reviewed real producer.
MyActivityItem fields are `{id,occurredAt,action,targetType,targetId,outcome,summary}`;
its summary allowlist is changedFields, fromState and toState only. Do not expose
operator-entered reasons or another actor's identity through the self projection.

List endpoints accept ISO from/to with from <= to, allowlisted action/outcome and
optional actorAccountId only for tenant-log permissions. Sort is occurredAt desc
then id desc (or explicit asc); no arbitrary JSON-path filters. Audit queries do
not recursively append audit events. Export-producing capabilities remain deferred;
their future event schemas need review before becoming registered actions.

<a id="dependencies"></a>

## DEPENDENCIES — Delivery order

Deliver the append port/adapter before the first role mutation. Read apps depend
only on this store/query contract; zero rows before emitters exist is valid. Document
download emitters join later without making their own audit persistence implementation.

<a id="test"></a>

## TEST — Domain proof obligations

Audit append failure rolls back role/account/document mutations. Runtime attempts
to UPDATE/DELETE audit rows fail, including same-tenant attempts. Cross-tenant and
other-actor self reads reveal no rows. Reject arbitrary summary keys, secrets and
oversized content. No rows are seeded as actual historical user activity; seed
fixtures used for isolated tests are explicitly fictional. Check cursor boundaries,
download unknown completion and empty export log without fake rows.
