# Skill — HCM navigation/catalog change

Use when adding, moving, hiding, or renaming an HCM Space/Page/feature placement.

- Keep feature implementation domain-owned; navigation placement does not move source ownership.
- Reuse an existing feature ID when the same feature appears in multiple navigation positions.
- Require stable IDs for Spaces, Pages and features.
- Specify required commercial entitlements and UI roles explicitly.
- Never treat catalog visibility as backend authorization.
- Update catalog tests for visibility changes.
- Update product/FDD documentation when navigation semantics change.
